# 外部實踐案例調研與架構融合分析報告

本報告分析評估社群創作者 Danny (@danny_techlife) 發布之 LINE 自動歸檔工作流系列文章，將其優缺點、架構策略與可借鏡之模式提煉並融入 `line-vault` 的演進藍圖中。

---

## 一、三篇貼文核心內容摘要

### 1. 第一篇：需求痛點與雲端歸檔方案 (Post: `DaLBWJAAVai`)
- **業務痛點**：委託人日常在 LINE 群組頻繁交流大量圖片、合約文件與數據，隨時間累積極難檢索且容易過期失效。
- **實作架構**：
  - 開發一個自動歸檔 LINE Bot，結合 **LINE Messaging API**、**Google Cloud Run**、**Google Drive API** 與 **Google Sheets API**。
  - 群組發送的圖片/檔案自動外送至 Google Drive，文字紀錄按群組/日期歸檔至 Google Sheets。
- **未來擴充理念**：
  - 設計預留空間串接 **Gemini API**，以自動分析圖片/文件、萃取重點、建立自訂分類標籤。

### 2. 第二篇：設計思考與部署路徑 (Post: `DaNhTp5AQRv`)
- **核心主張**：「真正花時間的反而不是寫程式，而是先把流程想清楚」：
  1. 規則與分類想怎麼定義？
  2. 檔案目的地要存放在哪裡？
  3. 要部署在哪裡，才能兼顧成本、維護跟未來擴充？
- **雲端 vs 本地部署折衷**：
  - **雲端**：GCP Cloud Run，串接 Google 生態（Sheets、Calendar、Drive）認證最順手，但需考量計費與前 90 天試用期。
  - **本地端**：若一般使用者想把資料完全留在本地電腦，可以在本地跑搭配 ngrok 開對外 Webhook，只需一台不關機的電腦。
- **規範先行**：發布 `spec.md` 規格書，推薦使用 Claude Code、Codex、Antigravity 等現代 AI 輔助加速開發與部署。

### 3. 第三篇：AI 介入時機與 Function Calling (Post: `DaNiUkBgc6u`)
- **AI 介入兩階段原則**：**「先完成資料收集、分類、儲存，再依需求決定是否把內容送給 AI 分析」**（嚴禁所有 raw data 盲目灌入模型）。
- **進階處理手段**：
  - 透過 **Function Calling（工具調用）** 讓 AI 根據視覺/文字分析結果自動觸發業務流程（如：幫圖片建立分類、收據萃取結構化表格寫入 Sheets、通知指定負責人）。
  - **成本與隱私防線**：採用輕量平價模型（如 Gemini Flash Lite，每日免費約 500 次呼叫），並**嚴格要求在呼叫外部 AI 前確認敏感機敏資料切勿外洩**。

## 二、方法與優缺點對照分析

| 維度 | Danny 的 LINE Bot 方案 (Cloud Run + Drive + Sheets) | LINE Vault 現行架構 (Windows 11 Native Vault) | 融合後的進化架構 (LINE Vault Hybrid) |
| :--- | :--- | :--- | :--- |
| **資料獲取方式** | 需手動將官方 Bot 拉入群組；**個人對話與社群(OpenChat)無法使用**，且受 Messaging API 費用與群組限制。 | **本機記憶體金庫直讀**（wxSQLite3 解密）；免 Bot、免拉群、個人/群組/社群全支援，且歷史對話全部可回溯。 | 保留本機無痕直讀作為 **核心資料源 (SSOT)**，兼具全量歷史與社群支援。 |
| **檔案留存位置** | 雲端 Google Drive。優點是跨裝置易分享，缺點是有容量成本且依賴網路。 | **本機自訂目錄 (依聊天室名稱分子資料夾)**。優點是 100% 隱私、離線可用、永久防過期。 | **雙軌自選 (Dual-destination)**：以本機子資料夾為基底，可選鏡像外送至指定 Google Drive。 |
| **AI 分析介入時機** | 兩階段處理：先收納後觸發，搭配 Function Calling 進行收據/報價結構化。 | 內建 100% 本地啟發式規則分析 + 待辦事項抽取。 | **借鏡兩階段與 Function Calling**：本地規則秒級出結論，外接可選 Gemini API 做深度視覺辨識。 |
| **隱私與機敏保護** | 需特別注意機敏資料不可盲目送入雲端 API。 | 預設完全在本地記憶體與硬碟運作，零機敏外洩風險。 | 貫徹本機脫敏機制；如需啟用雲端分析，先過濾個資與帳號資訊。 |

## 三、具體完善至 `line-vault` 改作計畫之項目

1. **落實「兩階段資料流水線 (Two-Stage Pipeline)」**
   - **Stage 1 (收集與實體儲存)**：背景定時器自動讀取本機 LINE，依設定將貼圖、圖片、影片、檔案按「聊天室名稱」分類落盤並入庫，不依賴任何外部 AI。
   - **Stage 2 (結構化抽取與分析)**：在本地以離線規則產出待辦清單與報告；後續擴充 Gemini Flash 視覺分析時，僅針對已落盤之特定收據/合約檔案進行隨選 (On-demand) 或背景脫敏呼叫。
2. **對齊「目錄存放規則與分類定義」之最佳實踐**
   - 本次已實作依「聊天室名稱」建立子目錄、清理非法字元，並允許自訂根目錄；後續可進一步借鏡其規範，支援以「年-月」二級資料夾或檔案類型細分子目錄。
3. **擴充「雲端 Google Drive / Sheets 外送鏡像」插件選項**
   - 列入 Phase 7 發展藍圖：使用者在本地完成防過期備份後，可自由選擇是否將特定監控聊天室的重點摘要與檔案外送至指定的 Google Drive / Sheets。
